# TransaFlow — பயனர் வழிகாட்டி (தமிழ்)

**குவாரியிலிருந்து சைட் வரை — போக்குவரத்து ERP.** நிறுவன அமைப்பு முதல் இன்வாய்ஸ் அனுப்புதல், பணம் வசூல்,
டிரைவர் சம்பளம், ரிப்போர்ட்கள் வரை TransaFlow-ஐ படிப்படியாக எப்படி பயன்படுத்துவது என்பதை இந்த வழிகாட்டி விளக்குகிறது.

> **எங்கிருந்து தொடங்குவது?** அத்தியாயங்களை வரிசையாகப் பின்பற்றுங்கள். அத்தியாயம் 1–3 ஒருமுறை மட்டும்.
> அத்தியாயம் 4–9 தினசரி வேலை. அத்தியாயம் 10–14 வாராந்திர / மாதாந்திர வேலை.
>
> குறிப்பு: அப்ளிகேஷனில் மெனு பெயர்கள் ஆங்கிலத்தில் உள்ளன. அதனால் இங்கே மெனு பெயர்களை ஆங்கிலத்திலேயே
> கொடுத்துள்ளோம் (உதா: *Operations → Bookings*).

## தொடங்கும் முன்

- **உள்நுழைவு:** TransaFlow லிங்கைத் திறந்து, நிர்வாகி கொடுத்த **username** மற்றும் **password** உள்ளிடுங்கள்.
  **Dashboard** திறக்கும். இடது மெனுவில் *TransaFlow* மேலே உங்கள் நிறுவன சுருக்கப் பெயர் (உதா: **PKC**) தெரியும்.
- **தற்காலிக password:** கணினி உருவாக்கிய அல்லது reset செய்யப்பட்ட password என்றால், முதலில் **Profile → Change password**
  திறக்கும். தற்காலிக password-ஐ தற்போதைய password ஆக உள்ளிட்டு, உங்கள் சொந்த password (8+ எழுத்துகள்) அமைக்கவும்;
  பிறகு அப்ளிகேஷன் திறக்கும்.
- **மொபைலில்:** மேலே இடது பக்கம் உள்ள **☰** தொட்டு மெனுவைத் திறக்கவும்.
- **கட்டாய புலங்கள்** **\*** குறியுடன் இருக்கும். அவை நிரப்பும் வரை Save பட்டன் வேலை செய்யாது.
- **தேதிகள்:** பழைய தேதிகளை உள்ளிடலாம் (உதா: நேற்றைய ட்ரிப்), ஆனால் **எதிர்கால தேதி உள்ளிட முடியாது**.
- **எண்கள் தானாக வரும்:** புக்கிங், ட்ரிப், இன்வாய்ஸ், ரசீது, சம்பள எண்கள் நிதியாண்டு வாரியாக தானாக உருவாகும்,
  உதா: `INV-2627/00001` (நிதியாண்டு 2026-27, இன்வாய்ஸ் 1).
- **Approve = இறுதி:** பெரும்பாலான ஆவணங்கள் முதலில் **Draft / Submitted / Pending** ஆக சேமிக்கப்படும்.
  **Approve** (அல்லது **Post**) செய்தால் மட்டுமே கணக்குகளில் பதிவாகும். அப்ரூவ் செய்த பின் திருத்த முடியாது —
  தேவைப்பட்டால் Cancel செய்து மீண்டும் உருவாக்குங்கள்.
- **சந்தா அறிவிப்பு:** உங்கள் திட்டம் முடிவதற்கு 3 நாட்கள் முன் மேலே மஞ்சள் நிற செய்தி வரும். நிறுவன நிர்வாகி
  **Renew now** கிளிக் செய்யலாம்.
- **பணிகள் (யார் என்ன செய்யலாம்):**

| பங்கு (Role) | யார் | செய்யக்கூடியவை |
|---|---|---|
| Company Admin | உரிமையாளர் / மேலாளர் | அனைத்தும் — பயனர்கள், கிளைகள், அமைப்புகள் உட்பட |
| Accountant | கணக்கு ஊழியர் | இன்வாய்ஸ், ரசீது, சம்பள போஸ்டிங், சப்ளையர் பேமெண்ட், ஜர்னல், நிதி ரிப்போர்ட் |
| Branch Manager | யார்டு பொறுப்பாளர் | தனது கிளையின் ஆபரேஷன்ஸ் மற்றும் பெரும்பாலான நிதி திரைகள் |
| Operator | டிஸ்பாட்சர் / கிளர்க் | புக்கிங், ட்ரிப், டீசல், செலவு, பராமரிப்பு (கணக்கு போஸ்டிங் இல்லை) |
| Viewer | ஆடிட்டர் / பங்குதாரர் | அனைத்தையும் பார்க்கலாம், எதையும் மாற்ற முடியாது |
| Driver | டிரைவர் (மொபைல்) | வாகனப் பிரச்சினை புகார், தனது சம்பள ஸ்லிப் பார்த்தல் |

### ஒருவர் மட்டும் நடத்தும் நிறுவனம் (ஒரே லாகின்)
ஒருவரே அனைத்து வேலைகளையும் செய்தால், நிறுவனம் onboard செய்யப்பட்டபோது உருவான **Company Admin லாகின் மட்டுமே போதும்** —
வேறு பயனர்கள் தேவையில்லை.
- Company Admin அனைத்து மெனுக்களையும் திறக்கலாம்: மாஸ்டர்கள், புக்கிங், ட்ரிப், டீசல், செலவு, இன்வாய்ஸ், ரசீது, சம்பளம்,
  பராமரிப்பு, ஸ்டோர், சப்ளையர் பில், கணக்குகள், ரிப்போர்ட், அமைப்புகள் — நிறுவனத்தின் **அனைத்து கிளைகளுக்கும்**.
- தான் உருவாக்கியதை தானே அப்ரூவ், போஸ்ட், பேமெண்ட் செய்யலாம். நிறுவனத்தில் ஒரே ஒரு செயலில் உள்ள ஊழியர் லாகின்
  இருக்கும் வரை *second person must approve* அமைப்பு தானாகவே புறக்கணிக்கப்படும்.
- நிர்வாகி தனது சொந்த லாகினை நீக்கவோ செயலிழக்கவோ முடியாது; ஒவ்வொரு நிறுவனத்திலும் குறைந்தது ஒரு செயலில் உள்ள
  Company Admin எப்போதும் இருக்கும் — எனவே நீங்கள் ஒருபோதும் வெளியே பூட்டப்பட மாட்டீர்கள்.
- பின்னர் ஊழியர்கள் சேர்ந்தால், சரியான role உடன் பயனர்களைச் சேர்த்தால் போதும்; வேறு எதுவும் மாறாது.

## அத்தியாயம் 1 — ஒருமுறை நிறுவன அமைப்பு (Company Admin)

### 1.1 System Settings — *Admin → System Settings*
**நோக்கம்:** இன்வாய்ஸ் மற்றும் எண் வரிசைக்கு தேவையான நிறுவன விவரங்கள்.
- **Company Profile:** பெயர், GSTIN, PAN, முகவரி, போன், இமெயில். *GSTIN மிக முக்கியம் — GST வகையை அதுவே தீர்மானிக்கும்.*
- **Financial Years:** **01-04-2026 முதல் 31-03-2027** போன்ற நிதியாண்டு **Open** நிலையில் இருக்க வேண்டும்.
  திறந்த நிதியாண்டுக்கு வெளியே உள்ள தேதியில் கணக்குகளில் எதையும் பதிவு செய்ய முடியாது.
- **Settings:** எண் முன்னொட்டுகள் (`INV-`, `TRP-`, `BKG-`), மற்றும்
  `REQUIRE_SEPARATE_APPROVER = true` (செலவு/இன்வாய்ஸ் உருவாக்கியவரே அப்ரூவ் செய்ய முடியாது),
  `BOOKING_QTY_TOLERANCE_PERCENT` (புக் செய்த அளவைவிட சில % அதிகம் ட்ரிப் அனுமதி) போன்ற விருப்பங்கள்.

### 1.2 Branch Master — *Masters → Branch Master*
**நோக்கம்:** உங்கள் அலுவலகங்கள் / யார்டுகள். ஒவ்வொரு வாகனம், டிரைவர், பயனர், ஸ்டோர் ஒரு கிளைக்கு சொந்தம்.
- **கட்டாயம்:** Code, Name. **பரிந்துரை:** GSTIN, Manager, Phone, Address.
- உதா: `HO` — *Head Office, கோயம்புத்தூர்* — GSTIN `33ABCPK1234F1Z5`; `SLM` — *சேலம் யார்டு*.
- **GSTIN ஏன் முக்கியம்:** கிளை GSTIN மாநிலமும் (33 = தமிழ்நாடு) வாடிக்கையாளர் மாநிலமும் ஒன்றாக இருந்தால் →
  **CGST + SGST**; வேறு மாநிலம் என்றால் → **IGST**.
- பயனர்கள், வாகனங்கள், டிரைவர்கள், வாடிக்கையாளர்கள், ஸ்டோர்கள் அல்லது பரிவர்த்தனைகள் உள்ள கிளையை
  **நீக்க முடியாது** — **Deactivate** செய்யுங்கள். கடைசி கிளையை நீக்க முடியாது.

### 1.3 Users & Roles — *Admin → Users & Roles*
ஒவ்வொரு ஊழியருக்கும் லாகின் உருவாக்குங்கள்: பெயர், username, password (8+ எழுத்துகள்), கிளை, **Role**.
மொபைல் ஆப் பயன்படுத்தும் டிரைவர்களுக்கு **DRIVER** role உடன் பயனர் உருவாக்கி, *Driver Master*-ல் இணைக்கவும்.

### 1.4 Dropdown Lists — *Admin → Dropdown Lists*
வாகன வகைகள் (Tipper, Trailer), கொள்ளளவு (10 T, 20 T), எரிபொருள் வகைகள், செலவு வகைகள், அளவுகள் — உங்கள்
சொந்த மதிப்புகளை இங்கே சேர்க்கலாம்.

## அத்தியாயம் 2 — மாஸ்டர்கள் (ஒருமுறை உருவாக்கி, தேவைப்படும்போது மாற்றலாம்)

> **வரிசை:** Material & Quarry → Customers → Vehicles → Drivers → Suppliers.

### 2.1 Material & Quarry — *Masters → Material & Quarry*
**நோக்கம்:** நீங்கள் எதை ஏற்றுகிறீர்கள், எங்கே ஏற்றுகிறீர்கள்.
- **Materials டேப்** — *Code\*, Name\*, Category\**, **Default UOM** (புதிய ஆர்டர் வரி தொடங்கும் அலகு, உதா: *Unit*),
  இயல்பு **மெட்டீரியல் விலை**, **போக்குவரத்து விலை**, **ராயல்டி**, **லோடிங் கட்டணம்** (அனைத்தும் *ஆர்டரின் ஒரு அலகுக்கு*).
  உதா: `MSAND` — *M-Sand* — Unit — மெட்டீரியல் ₹4,300, போக்குவரத்து ₹1,450, ராயல்டி ₹270, லோடிங் ₹180 (ஒரு யூனிட்டுக்கு).
- **Quarries டேப்** — குவாரி பெயர், இடம்; உதா: *மதுக்கரை குவாரி*.
- **Loading Locations** — லோடிங் இடங்கள் மற்றும் கட்டணம்; **Pricing** — தேதி வாரியான விலை.
- **UOM Master → Order units** — புக்கிங், ட்ரிப், இன்வாய்ஸில் பயன்படுத்தக்கூடிய அலகுகள். புதிய நிறுவனம் **Unit** மட்டும்
  (Active, Default) உடன் தொடங்கும்; Ton, KG, CFT … Inactive. கம்பெனி அட்மின் ஒரு அலகை **Active** செய்யலாம் அல்லது
  **Make default** செய்யலாம்; Default அலகை நிறுத்த முடியாது. ஒரு அலகை நிறுத்தினாலும் ஏற்கனவே சேமித்த ஆர்டர்கள் மாறாது.
  அலகுகளுக்கு இடையே அளவு **மாற்றப்படாது** (2 Unit என்றால் 2 Unit தான்). பொது அலகுகளை (Unit, Ton, KG …)
  பிளாட்ஃபார்ம் அட்மின் மட்டுமே மாற்ற முடியும்.
- **அடுத்து:** Customer Master.

## அத்தியாயம் 4 — புக்கிங் (வாடிக்கையாளர் ஆர்டர்) — *Operations → Bookings*
**நோக்கம்:** வாடிக்கையாளர் என்ன ஆர்டர் செய்தார் என்பதைப் பதிவு செய்தல்.
1. **Register Booking Request** கிளிக் செய்யவும்.
2. **Customer\*** மற்றும் **Delivery site**, முன்னுரிமை (priority) தேர்வு செய்யவும்.
3. மெட்டீரியல் வரிகள்: **Material\***, **Quantity\*** (உதா: 2), **Unit\*** (உதா: *Unit* — மெட்டீரியலின் இயல்பு அலகு
   அல்லது கம்பெனி Default தானாக வரும்), **Rate / Unit\***, **போக்குவரத்து விலை\***, **ராயல்டி\***, **லோடிங்\***,
   **GST %\*** (உதா: 5). இயல்பு விலைகள் மெட்டீரியல் மாஸ்டரில் இருந்து வரும். பட்டியலில் ஆர்டர் **2 Unit M-Sand** என தெரியும்.
4. சேமித்தால் நிலை **PENDING**. புக்கிங் மதிப்பு = அளவு × (மெட்டீரியல் + போக்குவரத்து + ராயல்டி + லோடிங்) + GST.
5. புக்கிங்கை **Approve** செய்யுங்கள். *அப்ரூவ் செய்த புக்கிங்கில் மட்டுமே ட்ரிப் திட்டமிட முடியும்.*

**தெரிந்து கொள்ள வேண்டிய விதிகள்**
- ட்ரிப் உள்ள புக்கிங்கை Reject செய்ய முடியாது; ஏற்கனவே சென்ற அளவைவிட குறைவாக புக்கிங் அளவை மாற்ற முடியாது.
- ஒரு புக்கிங்கில் ஒரு மெட்டீரியல் **ஒரே அலகில்** மட்டும். ட்ரிப் சென்ற பிறகு அந்த மெட்டீரியலின் அலகை மாற்ற முடியாது.
- புக் செய்த முழு அளவும் டெலிவரி ஆனதும் புக்கிங் தானாக **COMPLETED** ஆகும்.
- வாடிக்கையாளருக்கு இனி லோடு தேவையில்லை என்றால் **Close** செய்யலாம் (சாலையில் எந்த ட்ரிப்பும் இருக்கக்கூடாது).
- வாடிக்கையாளரின் **பர்ச்சேஸ் ஆர்டர்** (PO) நகலை புக்கிங்கில் இணைக்கவும்.

**அடுத்து:** ட்ரிப் திட்டமிடல்.

## அத்தியாயம் 5 — ட்ரிப், டிஸ்பாட்ச், டெலிவரி — *Operations → Trips & Dispatch*
**நோக்கம்:** குவாரியிலிருந்து சைட் வரை ஒவ்வொரு லாரி லோடும்.

### 5.1 ட்ரிப் திட்டமிடல்
**Plan Dispatch Trip** கிளிக் செய்து உள்ளிடவும்:
- **Booking\*** (அப்ரூவ் செய்தவை மட்டும் தெரியும்), **Trip date\*** (எதிர்காலம் கூடாது, புக்கிங் தேதிக்கு முன் கூடாது),
- **Vehicle** மற்றும் **Driver** (டிஸ்பாட்ச் செய்ய தேவை), **Quarry** மற்றும் **Loading point**,
- **புக்கிங்கை** தேர்ந்தெடுத்தால் படிவம் தானாக நிரம்பும்: வாடிக்கையாளர், டெலிவரி சைட், புக்கிங் குறிப்புகள் மற்றும் இன்னும் அளவு
  மீதமுள்ள ஒவ்வொரு மெட்டீரியலுக்கும் ஒரு வரி. ஒவ்வொரு வரியிலும் *Booked · On other trips · Remaining* மற்றும் விலை தெரியும்;
  மீதமுள்ள முழு அளவுக்கு **Use 6 Unit** அழுத்தவும், அல்லது லாரியின் அளவை உள்ளிடவும். புக்கிங்கில் உள்ள மெட்டீரியல்கள் மட்டுமே தேர்வு செய்ய முடியும்.
- மெட்டீரியல் வரி: **Material\*** (புக்கிங்கில் இருக்க வேண்டும்) மற்றும் **Quantity\*** (உதா: 2). அலகு எப்போதும்
  புக்கிங்கின் அலகுதான் (உதா: *Planned Qty (Unit)*) — ட்ரிப்பில் மாற்ற முடியாது.

சேமித்தால் நிலை **PLANNED**, எண் `TRP-2627/00001` போல வரும்.
அனைத்து ட்ரிப்களின் மொத்த அளவும் புக் செய்த அளவை (+ அனுமதி %) தாண்டக்கூடாது.

### 5.2 Dispatch → Complete
- லாரி குவாரியிலிருந்து புறப்படும்போது **Dispatch** (வாகனம் + டிரைவர் தேவை) → **DISPATCHED**.
- சைட்டை அடைந்ததும் **Complete** → **COMPLETED**.
- வரிசை மாறாது: PLANNED → DISPATCHED → COMPLETED. PLANNED நிலையில் உள்ள ட்ரிப்பை மட்டுமே Cancel செய்யலாம்.

### 5.3 எடைப்பாலம் (Weighbridge) மற்றும் POD
முடிந்த ட்ரிப்பைத் திறக்கவும் (**Edit**):
- **Loaded Qty** மற்றும் **Delivered Qty**, புக்கிங்கின் அலகில், உதா: 2.00 / 1.95 Unit → **குறைவு 0.05 Unit**
  (டன் புக்கிங் என்றால் எடைப்பாலம் டன்). டெலிவரி அளவு ஏற்றிய அளவைவிட அதிகமாக இருக்கக்கூடாது.
  **பில் போடுவது டெலிவரி அளவுக்குத்தான்.**
- **POD / டெலிவரி சலான் / LR** ஐ ட்ரிப் ஆவணங்களில் பதிவேற்றவும்.
- ட்ரிப் இன்வாய்ஸில் சேர்ந்த பின் அது பூட்டப்படும் (மாற்ற முடியாது).

**அடுத்து:** டீசல் & செலவுகள், பிறகு இன்வாய்ஸ்.

  **லிட்டர் விலை\***, **முந்தைய\*** மற்றும் **தற்போதைய ஓடோமீட்டர்\***, **பணம் செலுத்திய முறை\***, தேதி, பில் புகைப்படம்.

## அத்தியாயம் 7 — இன்வாய்ஸ் — *Finance → Invoices*
**நோக்கம்:** முடிந்த ட்ரிப்களுக்கு வாடிக்கையாளருக்கு பில் போடுதல்.
1. **Ready for billing** திறக்கவும் — இன்னும் பில் போடாத அனைத்து முடிந்த ட்ரிப்களும் தெரியும்.
2. **ஒரே வாடிக்கையாளரின்** ட்ரிப்களை டிக் செய்யவும் (அல்லது *select all of this customer*) →
   **One invoice for N trips**. (ஒரு ட்ரிப்புக்கு மட்டும் **Generate** பட்டனும் பயன்படுத்தலாம்.)
3. **DRAFT** இன்வாய்ஸ் உருவாகும்: அளவு = டெலிவரி அளவு, ட்ரிப்பின் அலகில் (உதா: *2 Unit*); விலைகள் புக்கிங்கில் இருந்து.
   வரி மதிப்பு = அளவு × (விலை + போக்குவரத்து + லோடிங் + ராயல்டி). **தள்ளுபடி GST-க்கு முன்பே கழிக்கப்படும்.**
4. தேவைப்பட்டால் டிராஃப்டை **Edit**: இன்வாய்ஸ் தேதி (எதிர்காலம் கூடாது, ட்ரிப் தேதிக்கு முன் கூடாது),
   Place of supply (2 இலக்க மாநில குறியீடு, உதா: 33), தள்ளுபடி, கட்டண விதிமுறைகள்.
5. **Approve** → **Customer Receivable** / **Freight Income** + **GST Liability** கணக்குகளில் பதிவாகும்.
   எண் `INV-2627/000xx`.
6. **Print / PDF** எடுத்து (அளவு அலகுடன் அச்சாகும், உதா: *2 Unit*), **கையொப்பமிட்ட நகல் / இ-வே பில்** இணைக்கவும்.

**GST உதாரணம்:** 19.8 டன் × ₹1,350 = ₹26,730 வரிக்குட்பட்ட மதிப்பு; GST 5% = ₹1,336.50 →
CGST ₹668.25 + SGST ₹668.25 (அதே மாநிலம்) → மொத்தம் ₹28,066.50. வேறு மாநில வாடிக்கையாளருக்கு IGST ₹1,336.50.

**விதிகள்:** ஒரு ட்ரிப்புக்கு ஒருமுறை மட்டுமே பில்; ஒரு இன்வாய்ஸில் ஒரு வாடிக்கையாளர் மட்டும்; அப்ரூவ் ஆன
இன்வாய்ஸை Cancel செய்தால் கணக்குப் பதிவுகள் திருப்பப்படும்; மறந்த ட்ரிப்களை **Unbilled completed trips** ரிப்போர்ட் காட்டும்.

**அடுத்து:** பணம் வசூல்.

## அத்தியாயம் 8 — வாடிக்கையாளர் ரசீது — *Finance → Customer Receipts*
**நோக்கம்:** வாடிக்கையாளர்களிடமிருந்து பெற்ற பணத்தைப் பதிவு செய்தல்.
1. **Record Payment Receipt:** **Customer\***, தேதி, **Amount received\***, **Payment method\***
   (Cash / Bank / UPI / Cheque), குறிப்பு எண் (UTR / செக் எண்).
2. தொகையை வாடிக்கையாளரின் **திறந்த இன்வாய்ஸ்களுக்கு** ஒதுக்கவும் (பழையது முதலில்). மீதி **அட்வான்ஸ்** ஆக இருக்கும்.
3. சேமித்து → **Approve**. இன்வாய்ஸ்கள் **PAID** / **PARTIALLY PAID** ஆகும்; கணக்கு: Cash/Bank ↔ Customer Receivable.
4. செக் நகல் / UPI ஸ்கிரீன்ஷாட் இணைக்கவும். **Customer Ledger** டேபில் நிலுவை இருப்பைப் பார்க்கலாம்.

### Settlement Dashboard (Customer Receipts → Settlement Dashboard)
- **Received in period / Settled against invoices / Advance not yet applied** — காலப் பொத்தான்கள் (This month, Last month,
  Financial year, All time) படி மாறும். **Customers owe**, **Overdue** எப்போதும் இன்றைய நிலவரம்.
- **Dues by age** — ஒரு பெட்டியைக் கிளிக் செய்தால் (Not yet due, 1–30, 31–60 … நாட்கள் தாமதம்) அந்த இன்வாய்ஸ்கள் மட்டும் தெரியும்.
- **Customers with dues** (அதிக நிலுவை முதலில்): **Receive** — அந்த வாடிக்கையாளருக்கு ரசீது; **Ledger** — நிலுவை இருப்பு;
  **Apply advance** — முன்பணத்தை அவர்களின் பழைய திறந்த இன்வாய்ஸ்களுக்கு ஒதுக்கும்.
- **கிரெடிட் லிமிட்:** வாடிக்கையாளர் நிலுவை + இந்த புக்கிங் மதிப்பு கிரெடிட் லிமிட்டை தாண்டினால் புக்கிங்கை அப்ரூவ் செய்ய முடியாது
  (0 = லிமிட் இல்லை). பணம் வசூலிக்கவும் அல்லது Customer Master-ல் லிமிட்டை உயர்த்தவும்.

**அடுத்து:** டிரைவர் செட்டில்மெண்ட் (மாதாந்திரம்).

## அத்தியாயம் 9 — டிரைவர் அட்வான்ஸ் மற்றும் சம்பளம் — *Finance → Driver Payroll*

### 9.1 அட்வான்ஸ் (எப்போது வேண்டுமானாலும்)
**Advances டேப் → Give Advance:** டிரைவர், தொகை, தேதி, செலுத்திய முறை (பணம் / வங்கி / UPI).
*Driver Advances* கணக்கில் பதிவாகும். இன்னும் எதுவும் பிடித்தம் செய்யப்படாவிட்டால் மட்டுமே அட்வான்ஸை Cancel செய்யலாம்.

### 9.2 மாதச் சம்பளம்
1. **Generate Payroll:** டிரைவர், **மாதம்**, வருடம்; விருப்பமாக அலவன்ஸ், **அட்வான்ஸ் பிடித்தம்** (நிலுவைக்கு மேல் கூடாது),
   பிடித்தங்கள் (அபராதம் / சேதம் / மற்றவை — காரணத்துடன்).
2. அந்த மாதத்தின் **முடிந்த ட்ரிப்களில்** இருந்து கணினி கணக்கிடும்:
   நாள் வாரியான ட்ரிப் → ஒரு நாளுக்கு ஸ்லாப் தொகை → **ட்ரிப் வருமானம்** + அடிப்படை + அலவன்ஸ் = **மொத்தம் (gross)**;
   **நிகர சம்பளம் = மொத்தம் − பிடித்தங்கள் − அட்வான்ஸ் பிடித்தம்**.
   உதா: நாள் 1 = 1 ட்ரிப் ₹500, நாள் 2 = 2 ட்ரிப் ₹1,000, நாள் 3 = 4 ட்ரிப் ₹1,000 → மொத்தம் ₹2,500;
   அட்வான்ஸ் ₹500 → நிகரம் ₹2,000.
3. **Approve** (ட்ரிப்கள் மீண்டும் கணக்கிடப்படும்) → **Post to Accounts** (சம்பளச் செலவு, அட்வான்ஸ் பிடித்தம்) →
   **Pay Salary** (பணம் / வங்கி, தேதி, குறிப்பு எண்).
4. **Salary Slip** PDF-ல் நாள் வாரியான விவரம் இருக்கும். டிரைவர்கள் தங்கள் ஸ்லிப்பை **My Salary**-ல் பார்க்கலாம்.

**விதிகள்:** ஒரு டிரைவருக்கு ஒரு மாதத்துக்கு ஒரு சம்பளப் பதிவு மட்டும்; எதிர்கால மாதம் கூடாது; Cancel செய்தால் அனைத்து
பதிவுகளும் திருப்பப்பட்டு அட்வான்ஸ் பிடித்தம் திரும்ப நிலுவையில் சேரும்.

## அத்தியாயம் 10 — பராமரிப்பு — *Maintenance & Stores*
1. **Maintenance Requests:** டிரைவர் (மொபைல்) அல்லது ஊழியர் **Report a problem** — வாகனம், பிரச்சினை, முன்னுரிமை,
   ஓடோமீட்டர், சேத புகைப்படங்கள். நிலை **OPEN**.
2. அலுவலகம் **Review** → **Approve** → **Convert to Work Order** (அல்லது Cancel — உதா: சாலையிலேயே சரி செய்யப்பட்டது).
3. **Work Orders:** **பார்ட்ஸ்** (ஸ்பேர் பார்ட் + அளவு) மற்றும் **லேபர்** வரிகள் சேர்க்கவும்; வேர்ஹவுஸில் இருந்து பார்ட்ஸை
   **Issue** செய்யவும் (ஸ்டாக் குறையும்; திருப்பிய பார்ட்டை மீண்டும் வழங்கலாம்); வேலையை **Start** செய்யவும்.
4. **Complete:** **உண்மையான செலவு** (ஸ்டாக் பார்ட்ஸ் + லேபர் + வெளிக் கட்டணம்) மற்றும் **வெளிச் செலவு எப்படி
   செலுத்தப்பட்டது** (Credit = வொர்க்ஷாப் பில், Cash, Bank) உள்ளிடவும். ஸ்டாக் பார்ட்ஸ் செலவு இன்வென்டரியில் இருந்து
   பழுதுச் செலவுக்கு மாறும்; வெளிப் பகுதி சப்ளையர் பில் (கடன்) அல்லது பணம்/வங்கி பேமெண்ட் ஆகும்.
5. திறந்த வொர்க் ஆர்டர் உள்ள வாகனத்தை புதிய ட்ரிப்பில் போட முடியாது. வழங்கிய பார்ட்ஸ் திருப்பப்படாத வொர்க் ஆர்டரை
   Cancel செய்ய முடியாது — முதலில் பார்ட்ஸைத் திருப்புங்கள்.

## அத்தியாயம் 11 — ஸ்பேர் பார்ட்ஸ் மற்றும் ஸ்டாக் — *Maintenance & Stores*
- **Spare Parts:** குறியீடு, பெயர், அளவு, இயல்பு விலை, **ரீ-ஆர்டர் அளவு**, புகைப்படம்.
- **Warehouses:** உங்கள் ஸ்டோர்கள் (ஒவ்வொரு கிளை/யார்டுக்கும் ஒன்று).
- **Stock → Opening stock:** ஏற்கனவே உள்ள அளவு **யூனிட் விலையுடன்**. **Receive stock:** வேர்ஹவுஸ், பார்ட், அளவு,
  **விலை**, சப்ளையர், பில் எண், **பணம் செலுத்திய முறை** (Credit → சப்ளையர் பில் தானாக உருவாகும்; Cash / Bank).
- ஸ்டாக்கில் **சராசரி விலை**, **மதிப்பு**, நிலை **OK / REORDER / OUT** தெரியும். விலை இல்லாத பழைய ஸ்டாக்கை
  **Set cost** மூலம் ஒருமுறை மதிப்பிடலாம்.
- **Inventory Transactions:** ஒவ்வொரு வரவு, வழங்கல், திருப்பல் — விலை மற்றும் வொர்க் ஆர்டருடன்.

## அத்தியாயம் 12 — சப்ளையர் பில்கள் & பேமெண்ட் — *Finance → Supplier Bills & Payments*
- **Bills:** தானாக உருவாகும் (கடன் ஸ்டாக் வரவு, கடன் வொர்க்ஷாப் வேலை) அல்லது வொர்க்ஷாப் / டயர் / அலுவலக பில்களுக்கு
  **New bill**: சப்ளையர், அவர்களின் பில் எண், தேதி, செலுத்த வேண்டிய தேதி (கிரெடிட் நாட்களில் இருந்து தானாக),
  வகை, வரிக்குட்பட்ட தொகை, GST. டிராஃப்டாக சேமித்து → **Approve** (செலவு + GST input / Accounts Payable).
- **Pay supplier:** சப்ளையர், தேதி, தொகை, முறை, குறிப்பு எண்; பில்களுக்கு ஒதுக்கவும் (அல்லது பழையது முதலில் தானாக).
  பேமெண்டை Cancel செய்தால் பில்கள் மீண்டும் திறக்கும்.
- **Supplier outstanding & ageing** ரிப்போர்ட் நீங்கள் கொடுக்க வேண்டியதையும் தாமதமானதையும் காட்டும்.

## அத்தியாயம் 14 — மாத இறுதி சரிபார்ப்பு பட்டியல்
1. **Pending approvals** ரிப்போர்ட் → டிராஃப்ட் புக்கிங், இன்வாய்ஸ், ரசீது, செலவு, டீசல், சம்பளம் அனைத்தையும் முடிக்கவும்.
2. **Unbilled completed trips** = 0 (டெலிவரி ஆன அனைத்துக்கும் பில் போடவும்).
3. மாதத்தின் அனைத்து டீசல் மற்றும் செலவுகளை அப்ரூவ் செய்து ட்ரிப்களுடன் இணைக்கவும் (**Unlinked costs** ரிப்போர்ட்).
4. மாதத்துக்கான **டிரைவர் சம்பளம்** — Generate → Approve → Post → Pay.
5. அனைத்து **வாடிக்கையாளர் ரசீதுகளையும்** பதிவு செய்யவும்; **Customer outstanding** பின்தொடரவும் (61–90, 90+ நாட்கள் முதலில்).
6. செலுத்த வேண்டிய **சப்ளையர் பில்களை** செலுத்தவும்.
7. **Document expiry** (இன்சூரன்ஸ் / FC / பர்மிட் / லைசென்ஸ்) சரிபார்க்கவும்.
8. GST தாக்கலுக்கு **Sales register** மற்றும் **GST summary** டவுன்லோட் செய்யவும்; **Monthly business summary** பார்க்கவும்.

## குடும்பச் செலவுகள் (விருப்பத் தொகுதி) — *Personal → Family Expenses*
**நோக்கம்:** உரிமையாளரின் குடும்பச் செலவுகளை (மளிகை, பள்ளிக் கட்டணம், மருத்துவம் …) **வணிகத்திலிருந்து தனியாக** பதிவு செய்தல்.
இது ரொக்கம், வங்கி, கணக்குகள், லாபம், டாஷ்போர்டு அல்லது எந்த வணிக ரிப்போர்ட்டையும் மாற்றாது.
- TransaFlow உங்கள் நிறுவனத்துக்கு இதை இயக்கியிருந்தால் மட்டும், **Company Admin / Admin** லாகினுக்கு மட்டும் தெரியும்.
- **Add Expense** → **Date\*** (எதிர்காலம் கூடாது), **Category\***, **Amount\***, **Payment mode\*** (Cash, UPI, Bank …),
  விவரம், குடும்ப உறுப்பினர், ரெஃபரன்ஸ் (விருப்பம்) → **Save**. பிறகு பில்லை இணைக்கலாம்.
  உதா: 02-10-2026 — Groceries — மாதாந்திர மளிகை — ₹4,500 — Cash.
- மேலே உள்ள கார்டுகள் **இந்த மாதம்**: மொத்தம், ரொக்கம், வங்கி / UPI, அதிக செலவான வகை. மாதம், வகை, முறை வாரியாக ஃபில்டர் செய்யலாம்.
- **Reports** டேப்: தினசரி, மாதாந்திர, வகை வாரியாக, பணம் செலுத்தும் முறை, ஆண்டு (நிதியாண்டு), மாத வாரியான வகை ஒப்பீடு,
  அனைத்து பதிவுகள் — ஒவ்வொன்றும் **Excel** மற்றும் **PDF**.
- **Categories** டேப்: வகையின் பெயரை மாற்ற, புதியது சேர்க்க அல்லது Inactive செய்யலாம். பயன்பாட்டில் உள்ள வகையை நீக்க முடியாது — Inactive செய்யவும்.
